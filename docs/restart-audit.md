# 任务重启与怪物行为排查

2026-10-11，基于 v0.3.5 源码的静态审查。用户报告：单人「雪花沉睡」快速重启后，历战王冰咒龙出现吐冰后尾刺，玩家观察到自己未被冰黏住。

目前没有复现并确认这段招式的触发条件，也没有确认工具导致了异常。游戏正常判定、判定时机与重启状态残留仍需要对照；不能把本次规避当成 AI 修复已验证。

## 写入范围

| 操作 | 源码中的写入对象 | 审查结论 |
| --- | --- | --- |
| 快速重启 | 玩家动作/衣装对象、任务控制对象与场景管理对象 | 跳过返回据点；代码没有单独确认冰冻、束缚和怪物行为状态已完整重建，存在需要实机对照的间接影响路径 |
| 稳定重启 | 游戏返回请求、任务结算状态与出发 UI | 先返回，再等待据点就绪并重新受理、出发；作为本次对照路径 |
| 配装、道具与猫饭 | 当前猎人的存档内存、食事对象和游戏道具栏刷新队列 | 未发现通过怪物对象链写入 AI；代码范围审查不等同于运行时地址正确性的证明 |
| 淡入淡出 | 可执行映像中的两个常量，操作结束恢复 | v0.3.6 仅在参数与支持版本的原值完全一致时缩短，避免覆盖其他工具或插件已经改动的数值 |
| 特殊怪物阶段判断 | 怪物对象链 | 只读；旧逻辑读取失败时允许快速重启，v0.3.6 改为稳定重启 |

后台连接轮询、聊天读取和快捷键监听不直接写怪物对象。游戏操作结束后不继续补写道具或猫饭。当前代码没有用于写怪物动作编号、AI 状态机或战斗速度的操作。

## v0.3.6 的排查措施

- 正在任务中使用快速模式，当前或目标任务为「雪花沉睡」时，改走完整返回据点再出发；其他任务继续使用原模式。这是针对用户报告的临时规避，会增加该任务的重启时间。
- 读取特殊怪物阶段失败时改用稳定流程，不再把读取失败解释成普通阶段。
- 淡入淡出参数只接受支持版本的原值，并沿用操作结束后的恢复流程。
- 日志记录应用版本、当前/目标任务、请求模式、采用模式、游戏阶段与加速选项，便于对照。

## 仍需确认

在重新启动游戏后，先用游戏自身流程进入同一任务记录现象，再与完整返回重启对照。记录吐冰时的目标、随从是否在场、玩家是否曾短暂进入黏冰区域，以及是否在该状态附近触发过重启。若能保留从吐冰开始的短片，可以核对招式是否已在脱离冰区前决定。

只有在同一环境中比较两条流程、或读到具体错误的状态，才能进一步判断因果。单次异常、成功出发日志和编译通过都不足以证明原因。第三方插件或任务修改若存在，也应保持一致并另行隔离；本项目不自动移动或停用用户的插件。
